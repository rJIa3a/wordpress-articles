# Universal Interlinker · локальная версия 0.2

Развитие существующего WordPress Context Linker. Сейчас работает локальный read-only сервис: страницы, граф, приоритеты, рекомендации, approve/reject, точный preview фрагмента HTML и история review. Публикация в WordPress и rollback ещё не реализованы и отключены, включая старый плагин.

## Запуск

Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-local.txt
python run.py
```

Откройте http://127.0.0.1:8000 . На Windows: `.venv\Scripts\activate` вместо `source`.

Нажмите «Загрузить статьи из репозитория» для имеющихся 50 выгрузок dagorod.ru либо добавьте URL и запустите crawler. После загрузки нажмите «Найти рекомендации». Данные сохраняются в `local-data/interlinker.sqlite3`. Эта папка исключена из Git.

## Подключение к базе dagorod.ru

Скопируйте `.env.example` в `.env` и заполните локально host, port, database, username, password и префикс таблиц. Пароли не отправлять в issue/PR и не коммитить. Пользователю MySQL нужны только права SELECT. Для недоступной извне БД используйте свой SSH-туннель/VPN; для прямого TLS можно указать `WP_DB_SSL_CA`.

Кнопка «Загрузить из MySQL» выполняет read-only транзакцию и читает опубликованные WordPress posts, их raw HTML и данные canonical/noindex Yoast. Импортируются permalink-структуры с postname/id/датой; category/author и plain permalink требуют отдельного resolver, поэтому при них импорт явно останавливается. Shortcodes и динамические блоки БД не рендерятся: перед будущей публикацией потребуется WordPress REST/render verification.

Фактическое подключение к рабочей базе не проверялось: реквизиты доступа не предоставлены. Адрес сайта сам по себе не дает доступа к MySQL.

## Поиск и проверка

- Поиск по блокам: BM25 со стеммингом + embeddings + слова заголовков + аббревиатуры + категории.
- LSA по умолчанию — экспериментальная ненейросетевая семантика. Для MiniLM установите `pip install -r requirements-benchmark.txt`, выберите MiniLM в настройках. Первая загрузка модели требует интернета.
- Ollama embeddings: локально `qwen3-embedding:0.6b` на localhost:11434. При недоступности модели выводится ошибка, без скрытого fallback.
- Дополнительный contextual veto: Ollama `qwen3:8b` проверяет уже найденную цель, может отказаться и обязан вернуть анкор из исходного текста. Порог confidence 0.85. Этот адаптер не тестировался с работающим Ollama; контракт ответа покрыт тестами.
- Приоритет URL/директории/категории даёт до 5 баллов только после relevance gate. Это бонус к ранжированию, пока не отдельный поиск возможностей для приоритетной страницы.
- Исключаются self-links, уже существующие на странице цели, одинаковый контент и повторные анкоры сверх лимита. Preview вставляет ссылку только в единственный свободный текстовый узел, без пересериализации HTML.
- Approve сохраняет решение, но не публикует его. «Вернуть на проверку» отменяет approve. Это не WordPress Undo.

## Проверка на 1150 статьях Википедии о городах

```bash
pip install -r requirements-benchmark.txt
python -m city_benchmark.collect --count 1150
OPENBLAS_NUM_THREADS=1 python -m city_benchmark.experiment --provider minilm
```

В Windows переменную OPENBLAS_NUM_THREADS можно опустить. Сбор возобновляется по сохраненному кэшу API. Все данные находятся в `local-data/cities/`:

- `manifest.json`: полнота, revisions, SHA-256, разбиение train/dev/test;
- `corpus.json`: очищенный текст и секции, без оригинальных ссылок;
- `gold.json`: скрытый эталон ссылок с анкорами и позициями;
- `CITY_REPORT.md`, `city-results.json`: фактические метрики после успешного запуска;
- `city-comparison.html`: предложения и оригинал на отложенных статьях.

Статьи выбираются из списка городов русской Википедии; для достижения 1150 используются дополнительные города соседних стран. Состав фиксируется в manifest. Сбор не расширяет цели по эталонным ссылкам. Оценка относится к связям между городами внутри корпуса; все прочие ссылки сохраняются отдельно. Из исходного wikitext исключены шаблоны, таблицы, ссылки на источники и служебные разделы. Метрика относится к поддерживаемому основному тексту, не к полному рендеру Wikipedia.

Реестр названий и алиасы из train дают цели-кандидаты. Лексический контекст и pretrained multilingual embeddings помогают выбрать уместное упоминание. Обучаемая logistic-модель калибруется по train; вариант и порог выбираются на dev; test используется после фиксации выбора. Это отдельный географический эксперимент; автоматическое применение его модели к URL dagorod.ru требует надежного сопоставления город→страница сайта и ещё не подключено к UI.

Разбиение по статьям 70/15/15, а не по регионам. Википедия — неполный редакционный эталон: несовпадение не доказывает бесполезность новой ссылки. Качество нельзя объявлять достигнутым по одному удачному показателю.

Тексты Wikipedia распространяются по CC BY-SA 4.0: https://creativecommons.org/licenses/by-sa/4.0/ . URL и номера версий сохраняются для атрибуции; авторы доступны через историю статей. Изменения при подготовке корпуса описаны выше. Код и инструкции хранятся в Git; raw snapshots, БД и веса моделей исключены.


GitHub Actions проверяет Python и PHP на ветках и PR. Плагин собирается как artifact; релиз возможен только при отдельном push тега `v*`. Изменения этого PR не должны автоматически публиковать версии плагина.

## Ограничения версии

- Crawler ограничен 25 URL на запуск, sitemap urlset и внутренними ссылками; sitemap indexes, JS rendering и полноценная обработка редиректов ещё не реализованы. Redirect responses пропускаются, targets не предлагаются.
- Старые страницы после нового crawl не удаляются автоматически. Это снимки, не гарантия актуального HTTP/noindex состояния всего сайта.
- Из robots учитывается robots.txt, meta robots и X-Robots-Tag. Sitemap-depth неизвестен и показывается отдельно.
- Orphan/weak считаются по загруженному корпусу. Граф показывает до 100 узлов.
- Нужны дальнейшие этапы: полный crawl, надежные page/block locators, PostgreSQL migrations, отдельный SEO objective retrieval, mapping Wikipedia→dagorod, подписанные changesets, REST Apply и rollback с проверкой конфликтов.

Исходные `prepare_articles.py`, `analyze_links.py`, `context_linker.py` сохранены как legacy. Их старые JSON-рекомендации не являются выходом нового сервиса.

## Проверенный городской baseline (9 сентября 2026)

Корпус собран: 1150 статей, 57 862 блока, 155 452 исходные ссылки,
10 133 ссылки между городами корпуса. Train/dev/test: 805/172/173 статьи.
Сохранённый лексический прогон: [отчёт](docs/CITY_REPORT.md),
[метрики](docs/city-results.json), [версии источников](docs/corpus-manifest.json).
На test: 1100 предложений; precision по паре страниц 67,9%,
recall 70,3%; precision по абзацу и цели 62,6%, recall 45,2%.
Это исходная точка, а не достигнутое качество Wikipedia.
Нейросетевой полный прогон не завершён; его результаты не заявляются.
После просмотра test дальнейшая настройка допустима только по train/dev;
для независимого подтверждения улучшений нужен новый holdout.

В UI доступен городской режим: выделяет город из заголовка страницы сайта,
учитывает назначение материала (достопримечательности / переезд) и отклоняет
контексты другого назначения. Это отдельное правило, а не перенос обученной
модели Wikipedia. Включение требует локального корпуса городов.
MiniLM сохраняет каждый пакет embeddings в SQLite: повторные запуски
используют рассчитанные векторы, в том числе после прерывания процесса.

## Следующая итерация качества

[Сравнение на dev](docs/REFINEMENT.md): точность абзац+цель выросла с 57,3% до
70,6%, полнота изменилась с 45,2% до 43,1%. Это подборочная оценка, не новый test.
Команда `python -m city_benchmark.refine` сравнивает исходную модель и новые
контекстные признаки без оценки test. Разбор ошибок сохраняется локально.
На обзоре сервиса показываются причины отклонений последней генерации;
API: `/api/sites/{site}/diagnostics`. Это позволяет объяснить нулевой результат,
не снижая пороги вслепую.

## Морфология и пропущенные ссылки

[Следующая итерация](docs/MORPHOLOGY.md): географические формы и ограниченные
повторы повышают dev precision до 71,4%, recall до 44,1%. Это подборочные
результаты; совпадение границ анкоров пока немного ухудшилось. В городской
режим сервиса перенесён географический разбор анкоров. Повторы остаются
экспериментальной настройкой benchmark.

## Контекст предложения

[Эксперимент и неопределённость](docs/SENTENCES.md): 670 совпадений абзац+цель,
precision 71,1%, recall 45,6% на dev. По сравнению с таким же режимом без
повторов полнота выросла, точность немного снизилась. Bootstrap не подтверждает
однозначный рост общего F0.5. Эксперимент воспроизводится флагом
`--city-morphology --sentence-context`; независимая проверка ещё нужна.
