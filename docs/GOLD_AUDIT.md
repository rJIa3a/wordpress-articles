# Аудит эталона и нейросетевой эксперимент

Проверены raw-версии 977 статей train/dev. Test-статьи не пересобирались и не оценивались. Для 131 814 исходных ссылок сверены позиции анкоров. У 9848 исправлены границы: окончания после `[[...]]` должны входить в анкор по linktrail-правилам. Тексты блоков не изменились. Исходные сопоставления редиректов сохранены.

Источник правила: https://www.mediawiki.org/wiki/Help:Links#Internal_links . В реализации поддержаны строчные латинские и русские буквы; расширение через nowiki не производится. Это не полноценный MediaWiki renderer: шаблоны и другие ранее исключённые элементы всё ещё не восстанавливаются.

На **неизменённых** 968 рекомендациях прежней модели:

| Метрика точных границ | Старый эталон | Исправленный |
|---|---:|---:|
| Совпадений | 531 | 685 |
| Precision | 54,86% | 70,76% |
| Recall | 35,05% | 45,21% |

Число оригинальных городских анкоров dev осталось 1515. Метрики по абзацу и цели и по паре страниц полностью совпадают со старыми. Это исправление измерения, не прирост способности алгоритма.

`gold-audit.json` содержит контрольную сумму семантически сериализованного v1 JSON (sort_keys=True, ensure_ascii=False). `gold-span-corrections.json` — пары [индекс оригинальной записи, новая конечная позиция]. Цели, начала анкоров и исходные тексты не меняются. Новый анкор получается срезом текста блока от исходного start до нового end. Полная исправленная разметка сохраняется в `local-data/cities/gold-audit/gold-v2-train-dev.json.gz`.

В ходе работы локальный несжатый gold оказался обрезан. Он восстановлен из сохранённого ZIP корпуса. Добавлен сжатый формат `.json.gz`, предпочтительный при чтении. Новый collector сохраняет gold сжато и ставит parser_version=2. Для прежнего поведения parser доступен clean(..., linktrail=False). Результаты разных версий эталона нельзя смешивать в одной серии без явного пересчёта.

## Нейросетевой прогон

Добавлен `python -m city_benchmark.neural`. Он использует предобученный multilingual MiniLM-L12-v2, описания 1150 целей и 24 447 уникальных локальных контекстов train/dev. Семантическая близость добавляется к предыдущей модели с относительными признаками. Контрольная модель обучается на тех же данных без нового признака. Порог выбирается на dev; test не оценивается.

Минимальная проверка реального провайдера завершена: получены векторы размерности 384. Полный расчёт запущен, но на момент подготовки этого отчёта **не завершён**, улучшение качества от embeddings не заявляется. Этот эксперимент добавляет семантический признак к существующим кандидатам; семантическое расширение shortlist — отдельный следующий этап.

Пакеты embeddings сохраняются в SQLite. Повторная команда использует кэш. `progress.json` сообщает стадию; `results.json` создаётся после полного обучения и оценки. Для текущего контролируемого сравнения используются прежние train/dev labels, а не смешение версий эталона.

```bash
python -m city_benchmark.audit_gold
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 python -m city_benchmark.neural
```

Для neural предварительно нужен кэш признаков от `refine --city-morphology --sentence-context`. Независимый holdout и контекстный reranker пока не реализованы этой итерацией.
